───────────────────────────────────────────────────────────────────────────────
THE ROOT PROBLEM:
───────────────────────────────────────────────────────────────────────────────

The loan admin page (/dashboard/loan-app) was throwing a runtime error that
broke the component rendering. The page compiled successfully (HTTP 200) but
failed on the client side when trying to restore archived loans.

THREE UNDEFINED FUNCTION CALLS were causing ReferenceError exceptions:

  1. Line 1716: mutate() ← undefined function
  2. Line 1809: mutate() ← undefined function  
  3. Line 1886: mutate() ← undefined function

These were in three different loan restoration functions:
  - restoreLoan() - restore single archived loan
  - restoreSelectedArchived() - restore selected loans
  - restoreAllArchived() - restore all archived loans

When any restoration happened, the error would crash the entire page because
the undefined mutate() call would throw a ReferenceError, stopping JavaScript
execution.

───────────────────────────────────────────────────────────────────────────────
THE SOLUTION:
───────────────────────────────────────────────────────────────────────────────

Replaced all THREE instances of mutate() with:

    void loadData({ silent: true })

This correctly reloads the loan workflow data after a restoration action,
ensuring UI stays in sync without showing a loader (silent: true).
