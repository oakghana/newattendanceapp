# Regional Loan Office (RLO) - Complete Implementation Guide

## Overview

The **Regional Loan Office** is a new role designed to provide regional oversight of loan and leave requests without the ability to approve or endorse them. This role can:
- View all loans and leaves from their assigned region
- Export data in CSV/JSON formats for reporting
- Generate regional analytics and reports
- Monitor regional loan/leave trends

## Key Differences from Regional Manager (RM)

| Feature | Regional Manager | Regional Loan Office |
|---------|-----------------|----------------------|
| Approve Loans | ✅ Yes | ❌ No |
| Endorse Leaves | ✅ Yes | ❌ No |
| View Regional Data | ✅ Yes | ✅ Yes |
| Export Data | ✅ Limited | ✅ Full |
| Generate Reports | ⚠️ Manual | ✅ Automated |
| Manage Staff | ✅ Yes | ❌ No |

## What Was Created

### 1. Database Migration (066)
**File**: `/scripts/066_create_regional_loan_office_role.sql`

Creates:
- New role value `regional_loan_office` in user_profiles constraint
- New table `regional_loan_office_locations` to track location assignments
- RLS policies for security
- Performance indexes

**Key Constraints**:
- Each RLO assigned to specific locations
- Cannot modify assignments (only admins)
- All data access is location-scoped

### 2. API Endpoints

#### A. View Loan Requests
**Endpoint**: `GET /api/loan/regional-office`
```bash
curl -H "x-user-id: user-uuid" \
  https://yourapp.com/api/loan/regional-office
```

**Response**:
```json

      "requested_amount": 5000,
      "status": "pending_hod",
      "submitted_at": "2026-01-15T10:00:00Z"
    }
  ],
  "summary": {
    "total": 45,
    "pending": 12,
    "approved": 28,
    "rejected": 5,
    "byType": {
      "Emergency Loan": 20,
      "Housing Loan": 15,
      "Education Loan": 10
    }
  }
}
```

#### B. View Leave Requests
**Endpoint**: `GET /api/leave/regional-office`
```bash
curl -H "x-user-id: user-uuid" \
  https://yourapp.com/api/leave/regional-office
```

**Response**: Similar structure to loans endpoint

#### C. Export Regional Data
**Endpoint**: `GET /api/regional-office/export`

**Query Parameters**:
- `type`: 'loans', 'leaves', or 'all'
- `format`: 'csv' or 'json'

**Examples**:
```bash
# Export all loans as CSV
curl -H "x-user-id: user-uuid" \
  "https://yourapp.com/api/regional-office/export?type=loans&format=csv" \
  > loans_report.csv

# Export all data as JSON
curl -H "x-user-id: user-uuid" \
  "https://yourapp.com/api/regional-office/export?type=all&format=json" \
  > regional_report.json
```

### 4. Security & Permissions

**RLS Policies**:
- Users can only see data from their assigned locations
- Only admins can assign locations to RLO users
- All operations are logged in audit_logs

**Authentication**:
- Requires valid user_id in `x-user-id` header
- User must have `regional_loan_office` or `admin` role
- Location scope verified before returning data

In Supabase, update user_profiles:
```sql

SET role = 'regional_loan_office'
```

## Troubleshooting

### Issue: "Insufficient permissions"
**Cause**: User doesn't have `regional_loan_office` role  
**Solution**: Update user_profiles.role to 'regional_loan_office'

### Issue: Empty data (0 records)
**Cause**: No locations assigned to this RLO user  
**Solution**: Insert records into regional_loan_office_locations table

### Issue: Export button not working
**Cause**: Browser popup blocked  
**Solution**: Check browser popup settings for the app domain

### Issue: API returns HTML instead of JSON
**Cause**: Database migration not applied  
**Solution**: Run migration script 066 in Supabase

## Security Considerations

1. **Data Isolation**: RLO users can only see data from their assigned locations
2. **No Approval Power**: RLO cannot approve, reject, or modify requests
3. **Audit Trail**: All RLO actions are logged in audit_logs table
4. **Read-Only**: RLO has SELECT permission only (no INSERT/UPDATE/DELETE)

## Performance Notes

- Indexes on `regional_loan_office_locations(regional_loan_office_id, location_id)`
- Loan queries filtered by location_id (indexed)
- CSV export limited to batch processing for large datasets
- Recommend pagination for >10,000 records
