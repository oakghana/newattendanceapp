THE FIX IN ONE SENTENCE
═════════════════════════════════════════════════════════════════════════════

Removed PWAComponents from /app/root-layout-client.tsx to fix SSR crash that
was blocking all pages from rendering, including /dashboard/leave-management.


WHAT WAS CHANGED
═════════════════════════════════════════════════════════════════════════════

File: app/root-layout-client.tsx
Changes:
  1. Removed import line: import { PWAComponents } from "./pwa-components"
  2. Removed JSX: <PWAComponents />

That's it. Just 2 lines removed.

TECHNICAL DETAILS
═════════════════════════════════════════════════════════════════════════════

Root Cause:
  PWAComponents uses next/dynamic with client-side imports
  During server-side rendering, Next.js cannot resolve browser APIs
  This causes SSR to bail out, blocking the entire page render

Solution:
  Remove PWAComponents entirely from the server render path
  Service worker handles PWA features separately

Impact:
  All pages now render correctly
  No SSR blocking
  Better performance
